## Project 7 — Visual Campaign (Month 4)

**Type:** Visual
**Duration:** 4 weeks
**Estimated workload:** 20–25 hrs/week
**Prerequisites:** All intensive phases (Weeks 1–12)

### Goal

Produce a campaign concept and key visual using the full visual framework — brief, pipeline, diagnosis, curation, direction, and refusal. The project must demonstrate that the framework survives contact with a real or simulated client brief.

### Brief

You are directing a visual campaign for a product, service, or idea of your choice. The campaign must have a stated intention, a defined audience, and a single key visual that carries the concept. The key visual must be produced through a visual pipeline you have designed, not a single generation.

### Deliverables

| Deliverable | Specification |
|---|---|
| **Working brief** | Intention, constraints, references, acceptance criteria, rejection conditions, risk assessment |
| **Pipeline documentation** | ComfyUI node graph, with every node explained as a decision |
| **First set** | 10 generated outputs, each diagnosed against the brief |
| **Second set** | 10 revised outputs, each diagnosed, with one accepted and three rejected, justified |
| **Decision log** | Minimum 20 entries, each naming the decision, the level, the alternative, and the outcome |
| **Written defense** | One page, naming the visual level, the decision, and the alternative |
| **Refusal** | One visual refusal, specific, justified, grounded in a slop criterion or ethical principle |
| **External critique record** | One structured critique session with a mentor, peer, or public channel, with a diagnosis of the feedback against the visual ladder |

### Pipeline Requirements

The visual pipeline must include:

- At least one conditioning layer (ControlNet pose, depth, or edge).
- One consistency mechanism (LoRA, IP-Adapter, or seed-locking).
- Documented variables and levers.
- A versioned state.

### Decision Log Requirements

Every decision entry must include:

| Field | Required |
|---|---|
| Date | Yes |
| Decision | Yes |
| Level (visual ladder) | Yes |
| Reason | Yes |
| Alternative rejected | Yes |
| Outcome | Yes |
| Revision if failed | Yes |

### External Critique Requirements

The critique must be structured. Do not ask "is this good?" Ask:

- What does the campaign seem to be trying to do?
- Where does your eye go first?
- At what level does the work fail — composition, value, construction, material?
- Which decision feels weakest?
- Does the work share the AI default visual signature?
- What would you change if it were yours?

### Standing Inquiry Integration

- **Weekly:** One sentence in the decision log.
- **Monthly:** One page answering "What is this work for?"

### Mastery Gate

The project is complete when:

- The brief scores 3 or higher on the Intent Architecture rubric.
- The pipeline scores 3 or higher on the Visual Pipeline I rubric.
- The decision log reconstructs every major decision with the alternative rejected.
- The written defense names the visual level, the decision, and the alternative.
- The refusal is specific, justified, and grounded.
- The external critique is logged and diagnosed.

### Common Failure Modes

- **Brief written after the output.** The student generates first, then writes a brief to justify. Fix: brief first. Always.
- **No rejection.** The student accepts the first output that looks good. Fix: at least three rejected outputs, with written diagnoses.
- **Slop drift.** The accepted visual shares the AI default signature (generic lighting, mid-tone dominance, uniform finish). Fix: compare against reference-class anchors. Apply the slop criterion.
- **No refusal.** The student delivers everything the pipeline produces. Fix: identify the output the pipeline would produce if the director did nothing. Refuse it.
- **Critique ignored.** The student receives feedback and does not diagnose it against the ladder. Fix: log the feedback, name the level, apply or push back.
